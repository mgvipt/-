## ✅ Чек-лист ПЕРЕД правкой любого файла (по порядку, без пропусков)

1. `git log --oneline -10 -- <файл>` — кто и когда трогал ЭТОТ файл. Коммиты за последние 48 часов =
   файл «горячий», в нём свежая работа другой сессии. Прочитай эти коммиты (`git show <sha> --stat`).
2. `git log --oneline --since='2 days ago'` — что вообще делалось в репо параллельно.
3. **Перечитай файл С ДИСКА непосредственно перед правкой.** Копия из контекста сессии устаревает.
   Никогда не восстанавливай файл «по памяти сессии».
4. Только ТОЧЕЧНЫЕ правки (edit конкретных строк). Полная перезапись файла (write целиком, scp, `cat >`)
   ЗАПРЕЩЕНА на проде.
5. **Перед коммитом: `git diff --stat`.** Если удаляется больше строк, чем требует твоя задача
   (делал «добавить тултипы», а diff показывает −95) — СТОП: ты сносишь чужую работу.
   Влей своё изменение В свежую версию файла, а не свою версию поверх.
6. Фронт делает PATCH модели → проверь, что ВСЕ поля есть в serializer (иначе PATCH молча затирает
   значения; кейс: привязка contact в карточке Дт/Кт, фикс `6ea9dce`).
7. Данные в БД: массовые операции только DRY_RUN → тест на 1-2 записях → live. Денежные записи
   (contact_id/deal_id платежей) НЕ перевешивать ради отображения. Бэкапы: `/var/backups/crm/daily/`.
8. В сообщение коммита добавляй метку агента: `[codex]` или `[claude:<сессия>]` — git-автор у всех
   один («Wallcov CRM»), без метки не видно, кто сделал коммит.
9. Запись в `crm-platform/docs/ИСТОРИЯ-ИЗМЕНЕНИЙ.md`: дата = СЕГОДНЯШНЯЯ (проверь `date`!), не дата
   из головы сессии. 26.08 записи ошибочно подписывались «19.08» — это тоже след устаревшего контекста.

## 🔴 ИНВАРИАНТ: дедуп исходящих IG/Meta (НЕ ломать — задвоение уже возвращалось 22.08 и 29.08)
Одно логическое исходящее = ОДНА запись Message. Instagram/Meta присылает «echo» нашего же отправленного сообщения обратно (webhook message_echoes) — его НЕЛЬЗЯ записывать как новое.
- send_message пишет `external_id = ext_id`, где ext_id от ChatPlace ≠ Meta-mid; echo всегда несёт Meta-mid. Поэтому сверка ТОЛЬКО по id (external_id/meta_external_id == mid) не ловит ChatPlace-отправку и window_risk-отправку без id → дубль (наше «director/Олег» + echo «ai_assistant/Юля (AI)»).
- В `apps/inbox/meta.py` (echo-ветка) ОБЯЗАТЕЛЬНА текстовая сверка ПЕРЕД созданием сообщения: если is_echo и есть mid — найти наше исходящее по тексту (direction=out, тот же text, meta_external_id пустой, за 10 мин) и доклеить mid (+снять window_risk→sent), затем continue. НЕ удалять эту проверку при рефакторингах echo/дедупа.
- Один IG-аккаунт валится в 2 канала (ChatPlace #1 = ИИ Юля, Meta #12 = зеркало) — не выключать, но следить чтобы echo зеркала не задваивал ответ ИИ.
