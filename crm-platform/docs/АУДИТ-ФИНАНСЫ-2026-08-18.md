## ГЛАВНЫЙ ВЫВОД
**Журнал (`Transaction`) — верный единый источник для ОБЩЕЙ кассы** (Σ доход/расход сходятся везде копейка-в-копейку). Расхождения возникают на уровне **привязки денег к сущностям** и **множества формул «прибыли»**.

## 🔴 Находки (по важности)

### 1. Опознание клиента ПО ИМЕНИ ломает карточки (корень «разных данных»)
- Σ Tx(in) журнала = **40.9 млн** (каждая операция 1 раз, верно). Но только **5.2%** дохода привязано к `contact_id`; 94.7% — легаси-импорт ФинМап без контакта, только текст `counterparty`.
- `finance()` (`crm/views.py:71-73`) добирает платежи правилом **byname** `counterparty istartswith "Имя "` → платёж размазывается по всем тёзкам. Платёж «Оксана Мельник» виден на **76 карточках** (все «Оксана*»).
- Итог: сумма «Дохід» по ВСЕМ карточкам = **105 млн (×2.57 к журналу)**; 87% дохода не видно ни на одной карточке, видимая часть задвоена. Это же ломает **аванс** и **прибыль** карточки (тот же `_match`).
- **Нарушает established-правило Олега** (CLAUDE.md): «опознавать по номеру переписки/телефону, никогда по частичному имени».
- **Фикс:** опознание по телефону/переписке; byname сузить до `iexact` полного «Имя Фамилия» и только для уникальных имён; легаси бэкфилить по телефону.

### 2. Мастера/поставщики не заведены как контрагенты
- `Contact` с ролью `master` = **0**. Выплаты мастерам = **409 операций, 4.48 млн ₴**, из них **408 без contact и без deal** — обезличенные проводки. Баланс мастера нигде не собирается.
- Имя мастера в тексте не нормализовано: Соколов = «Соколов Виктор Олегович» / «Соколов Виктор» / «Виктор Соколов» / «Соколов В.» — один человек под 4-5 написаниями.
- Поставщик «Будмаркет» (131 накладная, 34k) — без сводной карточки, размазан по 5 клиентским объектам.
- **Фикс:** мастера/поставщики = контакты (роль master/supplier), выплату привязывать к контакту-мастеру + к проекту (deal).

### 3. `PlannedPayment.contact` перегружен: кредитор ≠ объект
- Поле используется двусмысленно: иногда «кому платим (кредитор)», иногда «для кого закупили (объект)». Плитка «мы должны ему» на **5 клиентских карточках** показывает ложный долг (13.6k) — это закупки материалов под их заказ, а не долг им.
- **Фикс:** отдельный FK «кредитор/поставщик» ≠ «объект/клиент»; `finance()` считать 2 ролевых баланса явно.
