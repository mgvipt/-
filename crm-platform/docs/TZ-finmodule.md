# ТЗ: Финансы + Аналитика + Склад — единый продукт в CRM (перенос Cashflow)

> 2026-06-20. Источник: мультиагентный анализ кода Wallcov Cashflow (`/opt/finmap-bridge/src/services/kpi/`) + методология ATM. Связано: [[reference_atm_finmodel]], [[Код-карта]], [[project_wallcov_kpi]].

## Концепция
Связать склад + продажи + финансы в один контур: **Склад даёт себестоимость (FIFO) → Продажи дают выручку → Финансы собирают P&L и показывают точку безубыточности.** Один справочник «Финмодель» (проценты фондов/переменных/постоянных) правит владелец. Два раздела меню: Аналітика (право `analytics.view`) и Фінанси (`finance.view`).

## Структура вкладок
**Аналітика:** Продажі (KPI/воронка/топ-менеджеры/ROAS/конверсии/план-факт), Менеджери·ЗП, Плани, Склад (ведомость + оценка запасов FIFO + оборачиваемость).
**Фінанси:** ДДС/Грошовий потік, P&L (ATM 5 рівнів), Точка беззбитковості, Дебіторка, Налаштування фінмоделі (`finance.manage`).

## Ключевые формулы (из кода Cashflow)

### Точка безубыточности
- **(A) Реализованная в Cashflow** (`admin_router.py /widget/kpi/breakeven`) — переносим 1:1 как старт:
  - `margin_pct = 100 − Σ(revenue_fund.value %)`
  - `period_costs = (Σ(variable+fixed ₴/міс) + Σ(payment_fee ₴/угода)×100) × дней/30`
  - `breakeven_revenue = period_costs / (margin_pct/100)`
  - Прогресс `= факт/ТБ×100`; `daily_pace=факт/дней_прошло`; `required_daily=(ТБ−факт)/дней_осталось`; `ТБ_сделок=ТБ/средний_чек`.
- **(B) Правильная ATM** (целевая): `ТБ = УПР_Кат2 / (Маржа% × (1 − Переменные%/Маржа))`. Отличия: УПР делится на Кат2(в ТБ)/Кат3(отказные); переменные — % ОТ МАРЖИ, не от выручки.

### P&L по ATM (5 уровней)
`Выручка → −Прямые(% от выручки: поставщики/логистика/упаковка/комиссии) → =Маржа → −Переменные(% ОТ МАРЖИ: дивиденды/налоги/реклама/резерв) → =СКД → −УПР(₴/мес: ФОТ/аренда/CRM) → =Чистая`.

### Маржа сделки (`margin_calculator.py`)
`margin = revenue − original_price×48.78% − revenue×7%(логистика) − revenue×6%(упаковка) − Σ(payment×fee%) − 130₴(AI)`; `revenue = Σ(matched payments) − discount`. Скидка >15% → нет бонуса; >25% → блок.

### ЗП менеджера
- ATM (целевая): `ЗП_факт = ЗП_при_ТБ × (Выручка_факт / ТБ)`.
- Текущая: `4000 + online_paid×3% + online_paid×маржа%×(12/14/16/18 по плану) + 5×1300 KPI(гейт план≥100%) + 5×200 «0 ошибок» + отзывы(50/150)`.

### Деривация планов
`company_target = ТБ × 1.3`; `target_week = target_month×7/дней`; `coverage = Σ планов / company_target`.

## Бухучёт склада
- **Ведомость** (сделана 20.06): Початковий + Надходження − Продано = Кінцевий обліковий; Розбіжність = Факт − обліковий. Период from/to.
- **FIFO-себестоимость:** хранить cost партии прихода (StockLayer/unit_cost на in-движении); COGS списывать по слоям, не по скаляру `Product.cost`.
- **Оценка запасов:** Σ(остаток×cost) и Σ(остаток×price); оборачиваемость = COGS/средний_запас.
- **Проводки инвентаризации (разрыв склад↔финансы):** в `StockDocumentSerializer.create()` при kind=inv: надлишок→`record_income`(Надлишки інвентаризації), нестача→`record_expense`(Нестача складу).

## Финансы по клиенту (карточка клиента) — механика плиток (27.07.2026)

Плитки в шапке карточки клиента и как каждая считается (эндпоинт `GET /api/contacts/<id>/finance/`, `apps/crm/views.py` finance()):

- **Дохід** = сумма всех входящих транзакций клиента (`Transaction direction=in`), сматченных по `contact` ИЛИ по имени в `counterparty`. Это **реально записанные в CRM оплаты**.
- **Витрата (журнал+склад)** = **журнал-расходы** (out-транзакции клиента: закупки материалов под заказ, напр. МеталоБаза/БудМаркет) **+ Собівартість складу** (закупочная стоимость товаров, отгруженных клиенту со склада). Это ДВЕ разные суммы, поэтому «Витрата» может быть больше «Доходу».
- **Собівар. складу (COGS)** = Σ по ВСЕМ won-сделкам клиента: `кол-во × закупочная цена` товаров с `track_stock=True` (услуги track_stock=False сюда НЕ идут — они в «плановой закупке услуг»).
- **Прибуток** = Виручка − Собівар.складу − Закупки/послуги(журнал out). Маржа = Прибуток/Виручка.
- **Аванс (вільні гроші клієнта)** = `Дохід − Розхід(out) − ВСІ is_paid платежі сделок клиента (любой способ)`. Обычная оплата (нал/LiqPay) создаёт и доход, и платёж → в авансе гасятся (нетто 0); оплата «з авансу» дохода не создаёт → только уменьшает аванс. См. memory `project_crm_client_advance`.
- **Кредиторка (ми винні)** = сумма planned payable по клиенту. **Дебіторка (нам винні)** = planned receivable (торговая + займы + внутр. долг).

### ⚠️ ВАЖНО: ложный «убыток» у клиентов со старыми сделками из Битрикса
Прибуток сравнивает **Виручку (только записанные в CRM оплаты)** против **Собівартості по ВСЕМ won-сделкам**. Если у клиента много старых сделок, импортированных из Битрикса (деньги по ним прошли РАНЬШЕ/в Битриксе и в финансах CRM их НЕТ), то:
- их **себестоимость товаров считается** (сделка won, товары есть),
- но их **выручка не записана** (нет income-транзакции в CRM).
→ Себестоимость полная, выручка частичная → **ложный минус**.

Пример: Сергій Селіфонов (17359): 66 won-сделок на 237 794 ₴, Собівар 91 307 ₴, но Виручка в CRM только 100 000 ₴ (2 недавние оплаты) → «Прибуток −9 447». Реально клиент прибыльный: 237 794 − 91 307 − 18 140 ≈ +128 тыс. Причина минуса — только неполнота выручки по легаси-сделкам, а не убыток.
