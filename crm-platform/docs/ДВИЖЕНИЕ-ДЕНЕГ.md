# Движение денег в Wallcov-CRM — как что считается и где видно

> Обновлено 07.08.2026. Простыми словами: откуда деньги приходят, как разносятся, где смотреть результат.

## 1. Путь денег по типам оплаты

### LiqPay (онлайн картой)
1. Клиент платит по ссылке → **платёж по сделке** (`Payment`, оплачено) + **доход в журнал** (привязан к сделке) + **чек Checkbox** + стадия сделки двигается вперёд.
2. Банк присылает выплату LiqPay → проводится как **ПЕРЕВОД** (LiqPay-счёт → банк, сумма нетто) + **комиссия эквайринга** расходом. Доход НЕ дублируется (уже учтён при оплате).

### Наличка / касса
Приём оплаты в сделке → платёж (оплачено) + доход в журнал + чек. Всё сразу.

### Наложка Нова Пошта (после-оплата)
1. ТТН с «Контроль оплати» → клиент забирает на почте и платит → поллер НП видит «получено+оплачено» → **платёж наложки** + **чек Checkbox** + стадия. Деньги помечены «в пути» (ещё не на счету).
2. НоваПей перечисляет наложку на банк (часто ПАЧКОЙ за несколько посылок) → банк-матчер:
   - **доход по КАЖДОЙ сделке** (номинал наложки, привязан к своей сделке и клиенту),
   - **комиссия НоваПей** отдельным расходом на сделку (влияет на маржу),
   - платёж помечается «оплачено».
   Итог: Σдоходов − Σкомиссий = сумма выплаты (счёт сходится), маржа по сделке честная.

### Реквизиты
Оплата по реквизитам → стадия + чек. Доход в журнал.

## 2. Себестоимость (закупка) и маржа
- При продаже фиксируется **снимок себестоимости** товара в сделке (`DealItem.cost`).
- При отгрузке товар **списывается со склада** (реализация, один раз, без двойного счёта).
- Маржа сделки = Сумма − Себестоимость. Тот же снимок используется в бонусе ЗП со сделки.
- В карточке клиента себестоимость считается **только по сделкам с доходом в CRM** (легаси-сделки из Битрикса не дают ложный минус).

## 3. Где видно результат — по сущностям

| Что | Где смотреть |
|---|---|
| Оплата по сделке (оплачено/осталось) | **Карточка сделки** — блок оплаты, стадия |
| Себестоимость и маржа по сделке | **Карточка сделки → Товары** |
| Все деньги по клиенту (доход/расход/прибыль/маржа/скидки) | **Карточка клиента → Фінанси клієнта** (полные — по праву client.finance.full) |
| Сколько клиент купил | **Карточка клиента → шапка** «Купив у магазині» |
| Скидки клиента (список сделок) | **Карточка клиента → блок «Знижки»** (клик → список) |
| Каждая операция денег | **Фінанси → Операції** (журнал) |
| ЗП менеджера + KPI + скидки | **Фінанси → Плани → ЗП/KPI** |
| Деньги менеджера ПО ВОРОНКАМ | ЗП/KPI → клик «N сделок» → чипы воронок сверху |
| Прибыль по направлениям (факт) | **Фінанси → Аналітика → Направления** |
| P&L компании (норматив) | **Фінанси → Аналітика → P&L** |
| Отгрузка / склад / фото | **Склад** + блок «Відвантаження» в карточке сделки |
| Дебиторка / кредиторка | **Карточка клиента** + **Фінанси → Дт/Кт** |
| Аналитика склада (остатки, движение) | **Склад → Аналітика** (только владелец) |

## 4. Связки (кто на кого влияет)
- Сделка (цена, себестоимость, скидка) → **маржа сделки** → **% маржи в ЗП менеджера**.
- Оплата → **доход в журнал** → выручка клиента, выручка менеджера (оборот), Направления, P&L.
- Себестоимость + комиссии (LiqPay, НоваПей) → **расход** → маржа/прибыль.
- Скидка → уменьшает сумму сделки → уменьшает маржу (видна отдельно в карточке клиента и в ЗП).
- Наложка НоваПей → доход по сделке + комиссия расходом → честная маржа наложки.

## 5. Что НЕ дублируется (проверено аудитом)
- Доход книжится **один раз** (дедуп по банковскому REF / external_id / окно 180с).
- Реализация склада **идемпотентна** (нет двойного списания).
- Выплата LiqPay — перевод, не второй доход.
- Направления ⟷ P&L ⟷ Журнал сходятся точно (дельта 0).


### Аванс клиента (обновлено 17.08.2026)
**Вільний аванс = Дохід − Розхід − Σ по кожній сделці min(оплата, сума сделки).** Переплата понад суму сделки лишається авансом (не гаситься). Синхронно: `finance()` (плитка) і `accept_payment` (провайдер advance, `_avail`). Рахується від РЕАЛЬНОГО доходу → дубль-платіж без доходу не роздуває аванс.
