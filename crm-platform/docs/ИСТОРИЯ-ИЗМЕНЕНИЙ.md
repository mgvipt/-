## 13.07.2026 — В карточке платежа появился выбор «Клиент (объект)»

**Что попросили:** в окне операции (доход/расход) из карточки клиента нельзя было выбрать «Клиент (объект)», как в журнале — поэтому платёж нельзя было привязать к нужному клиенту.

**Что сделали:** добавили поле «Клиент (объект)» с поиском по имени/телефону (тот же компонент, что в журнале). Теперь любую операцию можно привязать к клиенту прямо из карточки платежа.

## 13.07.2026 — Удаление сделки прямо из карточки клиента

**Что попросили:** в карточке клиента в блоке «Сделки клиента» — возможность удалить сделку прямо в строке, с проверкой права (если есть право удалять сделки — доступно и тут, как везде).

**Что сделали:** в каждой строке сделки появилась корзинка 🗑 — удаляет сделку (с подтверждением). Кнопка видна только тем, у кого есть право «удаление сделки» (deal.delete) — то же право, что в карточке сделки и при массовом удалении. Без права кнопки нет, и сервер тоже не даст удалить.

**Где в системе:** карточка клиента → блок «Сделки клиента» → 🗑 в строке сделки.

## 13.07.2026 — Фонды теперь подтягиваются у менеджеров (не только у управляющих)

**Проблема:** у менеджера (например, Илоны) в карточке дохода/расхода не подтягивался список «Фонд (статья)». Причина — список фондов требовал право «управление финансами», которого у менеджера нет.

**Что сделали:** читать список фондов теперь может любой, кто работает с финансами или создаёт доход/расход (как уже было с «Направлениями»). Редактирование самих фондов осталось только у управляющих. Фонды теперь видны у всех менеджеров в выпадающем списке.

**Где в системе:** карточка дохода/расхода → поле «Фонд (статья)».

## 13.07.2026 — В карточке дохода/расхода подтягиваются контрагенты (автоподбор)

**Что попросили:** в окне «+ Доход»/«+ Расход» из карточки клиента поле «Контрагент» не подсказывало уже существующих контрагентов (в отличие от журнала).

**Что сделали:** добавили автоподбор — при вводе в поле «Контрагент» выпадают уже заведённые контрагенты/клиенты (тот же список, что в журнале). Меньше опечаток и дублей.

## 13.07.2026 — Карточка дохода/расхода в карточке клиента = зеркало журнала (появился выбор «Кредиторка/Дебиторка»)

**Что попросили:** в карточке клиента при «+ Доход»/«+ Расход» не было выбора «Кредиторка» (мы должны) / «Дебиторка» (нам должны), как в журнале. Нужно, чтобы окно было точь-в-точь как журнальное — и для дохода, и для расхода.

**Что сделали:** добавили в это окно переключатель:
— для расхода: «💸 Оплата сейчас» (сразу в журнал) / «🕐 Кредиторка (оплатим позже)» — попадёт в Дт/Кт как долг, а в журнал — после кнопки «Оплачено»;
— для дохода: «💰 Деньги пришли» / «🕐 Нам должны (дебиторка)».
Клиент подставляется автоматически. Работает так же, как в журнале.

**Где в системе:** Карточка клиента → «+ Доход» / «+ Расход» → переключатель под полем «Направление».

## 11.07.2026 — Починили звук на входящих звонках (менеджер не слышал клиента)

**Проблема:** на входящих звонках менеджер не слышал клиента (клиент менеджера слышал). Исходящие и приём звонка работали.

**Причина:** накануне веб-телефон переделали так, что во время звонка окошко «переезжает» в отдельный слой поверх страницы. Но вместе с ним переезжал и невидимый аудио-элемент, через который идёт звук. На входящем звонке звук успевал прицепиться ДО переезда — и в момент переезда терялся. На исходящем окошко переезжало заранее, поэтому там звук был.

**Что сделали:** вынесли аудио-элемент из «переезжающего» окошка — теперь он всегда на месте и звук не теряется, независимо от того, входящий звонок или исходящий.

**Где в системе:** веб-телефон в CRM (правый нижний угол), входящие звонки.

## 11.07.2026 — В карточке клиента можно сразу создать перевод между счетами

**Что попросили:** в карточке дохода/расхода (которая открывается прямо в карточке клиента) не было возможности сделать «перевод между счетами».

**Что сделали:** вверху окна операции добавили переключатель **💰 Доход / 💸 Расход / ⇄ Перевод**. Если выбрать «Перевод» — показываются два счёта (откуда → куда) и поле «зачислено получателю» (на случай разной валюты). Перевод не считается ни в доход, ни в расход — просто движение денег между кассами. Для уже созданной операции по-прежнему работает кнопка «Переделать в перевод».

**Где в системе:** Карточка клиента → «+ Доход» / «+ Расход» → переключатель вверху окна.

## 11.07.2026 — Карточка дохода/расхода открывается прямо в карточке клиента

**Что попросили:** когда в карточке клиента жмёшь «+ Доход» или «+ Расход» — не перебрасывать в Журнал, а открывать точно такое же полное окно операции прямо тут, с уже подставленным клиентом.

**Что сделали:** кнопки «+ Доход» / «+ Расход» теперь открывают полную карточку операции поверх карточки клиента (не уводят в журнал). В ней всё как в журнале: сумма, дата, категория, контрагент, счёт, фонд, направление, канал, комментарий, чек/документы, «переделать в перевод», а также распределение суммы между подразделениями (кто заплатил → остальным долг). Клиент подставляется автоматически. Кнопка «💳 Оплата/долг» осталась отдельно — для быстрой дебиторки и оплаты по сделке.

**Где в системе:** Карточка клиента → блок «Финансы» → «+ Доход» / «+ Расход».

# История изменений Wallcov-CRM

> **Что это.** Живой журнал всех доработок CRM простым языком — без технических терминов.
> Каждый раз, когда Олег просит что-то добавить или изменить, сюда дописывается запись:
> **дата → что попросили → что сделали → где это в системе**.
>
> **Как пополняется.** Автоматически при каждой доработке (правило в рабочем протоколе Claude).
> Документ лежит в репозитории `mgvipt/-` (папка `crm-platform/docs/`) и после каждого коммита
> сам заливается на GitHub — то есть история всегда сохранена и её не потерять.
>
> Новые записи добавляются **сверху** (последнее — первым).

## 2026-07-11

**Приложение «Wallcov Замер»: правильный расчёт материалов по эффектам.**
- Раньше в приложении был упрощённый расчёт (одно покрытие). Теперь приложение берёт настоящий прайс из твоей Google-таблицы (расход кг/м² и цена) — правишь таблицу, приложение обновляется само (раз в сутки).
- Появились «эффекты»: выбираешь эффект — приложение само подставляет весь состав (грунт глубокого проникновения + база/грунт + декор) и считает, сколько нужно и сколько стоит на твою площадь. Клиенту так проще; мастер может собрать и вручную.
- Инструменты (валики, шпатели, кельмы) — отдельным списком из каталога CRM, добавляются кликом.
- Технически: новый адрес `/api/pricelist/` отдаёт эффекты, материалы и инструменты.


**Приложение «Wallcov Замер»: клиенты теперь становятся лидами.**
- В приложении для замера стен добавили выбор на входе: «Я делаю ремонт у себя» (клиент) или «Я мастер/сотрудник».
- Когда клиент оставляет имя и телефон и отправляет свой замер — в CRM автоматически создаётся **лид в воронке «Лиды»** с его контактом и замером (сколько м² покрытия нужно, размеры стен, длина по полу, площадь пола).
- Учётные записи не создаются — клиент просто попадает в CRM как лид, менеджер видит замер прямо в карточке. Повторная отправка в течение 10 минут не плодит дубли.
- Мастера как и раньше отправляют замер в сделку воронки «Покрытия для стен».


**Прибыль по клиенту в карточке.**
- В карточке клиента строка «Прибуток по клієнту»: Выручка − Себестоимость склада − Закупки/услуги = Прибыль.
- Складские товары считаются из сделок (себестоимость авто при отгрузке), товары под заказ и услуги мастеров — из журнала. Без двойного счёта.
- Правило: складские товары — в сделку; товары под заказ (закупаем в другом магазине) — только в журнал (доход от клиента + расход/кредиторка магазину).

**Оплата клиента через журнал → попадает в «Оплачено» сделки.**
- В карточке клиента у «+ Дохід» появился выбор сделки. Привязал доход к сделке — платёж попадёт в «Оплачено» сделки и стадия двинется вперёд (как при обычном приёме оплаты). Работает и из журнала.
- Показывается остаток по сделке; если сумма не совпадает — предупреждение: меньше = частичная (внесёшь остаток позже), больше = переплата.
- Защита от двойного счёта: платёж, уже принятый через сделку, журнальный доход не задваивает. Расходы и импорты не затрагиваются.

## 2026-07-10 (вечер)

**Фильтры операций + «Купив у нашому магазині».**
- В блоке операций рядом с «Показувати» добавлены фильтры: по «Кому/від кого», по «Клиент (объект)» и по периоду (дата от — до). Пересчитывает список и плитки Доход/Расход.

**Столбец «Клиент (объект)» + все платежи контрагенту.**
- В операциях виден клиент-объект, к которому относится платёж (может отличаться от карточки, где находишься), кликабельно.
- Карточка поставщика (напр. Будмаркет) теперь показывает ВСЕ платежи ему, и напротив каждого — объект/мастер, кому реально пошли деньги.

**Столбцы «Кому/від кого» и «Сделка» в операциях.**
- В блоке операций видно, кому оплачено (расход) или кто оплатил (доход), и к какой сделке привязана операция.

**Удаление операций + шапка таблицы в карточке клиента.**
- В блоке операций теперь есть шапка с названиями столбцов (Дата / Сумма / Категория / Сделка), названия ровно над данными.
- Операцию можно удалить прямо в строке (корзина) или массово галочками («Удалить выбранные»), с подтверждением. Доступно тем, у кого право на финансы.

**Карточка операции открывается на месте.**
- Теперь клик по доходу/расходу в карточке клиента открывает карточку операции **прямо тут (модалкой)**, без перехода в журнал. Все поля видно и можно редактировать/удалить, перейти в сделку.

**Страница «Что нового» прямо в CRM.**
- В меню слева добавлен пункт «Що нового» — заходишь и читаешь всю историю доработок простым языком, не выходя из CRM. Копия по-прежнему на GitHub.

**Доходы и расходы в карточке клиента стали кликабельными.**
- Клик по любой операции открывает ту же карточку, что и в Журнале (посмотреть/изменить). Видно, к какой сделке привязана операция — по номеру переход в сделку.

**Выравнивание заголовков таблиц.**
- По всему CRM поправил шапки списков, где заголовки «уезжали» от значений (сумма теперь над суммой, стадия над стадией) — карточка клиента, аналитика, финансы.

## 2026-07-10

**Карточка клиента — история операций стала полноценной.**
- Внизу карточки теперь можно выбрать, сколько строк показывать (15 / 50 / 100 / 200 / 500), список прокручивается, а если операций больше — переключаются страницы (у Будмаркета, например, 595 операций — 12 страниц).
- В каждой строке расхода видно, **к какой сделке** он относится (если это объект). По номеру сделки можно кликнуть и сразу перейти в её карточку.
- Где: карточка любого клиента → блок «Фінанси клієнта».

**Дебиторка «нам винні» (нам должны).**
- В карточке клиента добавлена плитка «Дебіторка (нам винні)» — видно, сколько клиент нам должен.
- Завести долг можно прямо из карточки: у кнопки «+ Дохід» выбор «💰 Гроші прийшли / 🕐 Нам винні (дебіторка)».
- При дебиторке выбирается характер: **🛒 Продажа** (клиент должен за товар — это будущая прибыль) или **🤝 Заём** (я дал свои деньги в долг — возврат НЕ прибыль, прибыль только проценты; такой человек — заёмщик/должник). Система считает их раздельно, чтобы займы не раздували прибыль.

**Контрагент стал кликабельным + фильтр.**
- В Журнале и во вкладке «Дебет/Кредит» имя контрагента — ссылка: клик открывает карточку клиента.
- В «Дебет/Кредите» появился фильтр по контрагенту (поиск сверху).

**Телефония доведена под ключ** (несколько дней работы).
- Оба входящих номера (Алмаз и Салон) звонят менеджерам в CRM, окно звонка по центру экрана с данными клиента (кто звонит, сколько потратил, последняя сделка).
- Голос слышно быстро и чётко, гудок прекращается при поднятии трубки.
- Звонок приходит только на одну активную вкладку (не дублируется), исходящие тоже показываются по центру.
- В правах телефонии сделаны отдельные доступы: баланс линий, очередь, входящие/исходящие, «видеть все звонки или только свои».

**Мелочи этого периода:** убрано мигание блоков при обновлении списков; в аналитике скрываются воронки, к которым у сотрудника нет доступа; починена привязка чата к карточке канбана; адресная доставка Новой Почты (список улиц) заработала.
